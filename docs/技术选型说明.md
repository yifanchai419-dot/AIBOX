## 一、技术选型原则

### 1.1 核心原则

| 原则                   | 说明                                       |
| :--------------------- | :----------------------------------------- |
| **最节约最经济** | 优先选择开源免费工具，避免不必要的商业依赖 |
| **轻量级优先**   | 选择轻量级框架和库，降低部署复杂度         |
| **模块化设计**   | 代码按模块清晰划分，便于维护和扩展         |
| **容错性强**     | 支持Mock模式，具备完善的异常处理机制       |
| **标准接口**     | 使用标准API接口，便于模型切换和扩展        |

### 1.2 技术栈总览

| 类别                | 技术选型                  | 版本   | 选型理由                                      |
| :------------------ | :------------------------ | :----- | :-------------------------------------------- |
| **编程语言**  | Python                    | 3.10+  | 生态成熟，AI/数据处理库丰富，适合快速开发     |
| **前端框架**  | Streamlit                 | 最新版 | 轻量级Web框架，快速构建交互式界面，学习成本低 |
| **RSS解析**   | feedparser                | 6.0+   | 成熟的RSS解析库，支持多种RSS格式              |
| **网页抓取**  | requests + beautifulsoup4 | 最新版 | 组合成熟稳定，支持HTTP请求和HTML解析          |
| **数据库**    | SQLite                    | 3.30+  | 本地轻量数据库，无需额外服务，适合单机部署    |
| **向量库**    | ChromaDB                  | 0.4+   | 本地向量数据库，支持相似度搜索，适合查重场景  |
| **大模型API** | OpenAI SDK                | 1.0+   | 标准接口，兼容DeepSeek等模型，便于切换        |

#### 2.1.2 网页抓取

| 技术       | 选型           | 理由                                                                         |
| :--------- | :------------- | :--------------------------------------------------------------------------- |
| HTTP客户端 | requests       | - 简洁易用的HTTP请求库- 支持会话保持、代理等- 成熟稳定，文档完善             |
| HTML解析   | beautifulsoup4 | - 强大的HTML/XML解析器- 支持多种解析器（html.parser/lxml）- 灵活的选择器语法 |
| 文本清洗   | html2text      | - 将HTML转换为纯文本- 保留基本结构（标题、列表）- 轻量级，依赖少             |

#### 2.1.3 异常处理策略

| 异常类型 | 处理方式                                   |
| :------- | :----------------------------------------- |
| 网络超时 | 设置30秒超时，捕获`requests.Timeout`     |
| 连接失败 | 捕获`requests.ConnectionError`，记录日志 |
| HTTP错误 | 捕获`requests.HTTPError`，根据状态码处理 |
| 解析失败 | 捕获解析异常，跳过当前条目                 |
| 空数据   | 检查返回数据，无数据时标记为异常但继续流程 |

### 2.2 处理模块 (`src/processor.py`)

#### 2.2.1 去重算法

| 技术       | 选型                                                 | 理由                                                             |
| :--------- | :--------------------------------------------------- | :--------------------------------------------------------------- |
| 向量数据库 | ChromaDB                                             | - 本地部署，无需额外服务- 支持向量相似度搜索- 轻量级，资源占用低 |
| 嵌入模型   | text-embedding-3-small (OpenAI) / DeepSeek Embedding | - 高性价比的嵌入模型- 支持中文语义理解- API调用成本低            |

**去重流程**：

1. 将新采集内容转换为向量
2. 在ChromaDB中搜索相似度≥0.85的已有内容
3. 命中则判定为重复，跳过该条目

#### 2.2.2 质量打分

| 维度     | 技术实现                      | 权重 |
| :------- | :---------------------------- | :--- |
| 内容质量 | 大模型API评估内容完整性和深度 | 40%  |
| 时效性   | 根据发布时间计算衰减系数      | 30%  |
| 权威性   | 预设信源权重表                | 20%  |
| 相关性   | 向量相似度比对核心主题        | 10%  |

#### 2.2.3 自动分类

| 技术     | 选型                    | 理由                                               |
| :------- | :---------------------- | :------------------------------------------------- |
| 分类模型 | 大模型API（零样本分类） | - 无需训练数据- 支持动态分类标准调整- 分类准确性高 |

**分类类别**：

1. 模型发布
2. 产品更新
3. 行业动态
4. 论文研究
5. 技巧观点

### 2.4 向量库模块 (`src/vector_db.py`)

| 技术       | 选型              | 理由                                                   |

## 四、大模型API选型

### 4.1 主模型选型

| 模型                  | 平台          | 优势                           | 劣势              |
| :-------------------- | :------------ | :----------------------------- | :---------------- |
| **DeepSeek R1** | DeepSeek      | 性价比极高，长上下文，支持中文 | API稳定性待验证   |
| **GPT-4o-mini** | OpenAI        | 稳定性高，模型效果好           | 成本较高          |
| **Qwen 2**      | Alibaba Cloud | 中文支持好，成本适中           | API接入复杂度较高 |

**推荐方案**：使用DeepSeek R1作为主模型，OpenAI GPT-4o-mini作为备选

### 4.2 嵌入模型选型

| 模型                             | 平台     | 优势                 |
| :------------------------------- | :------- | :------------------- |
| **text-embedding-3-small** | OpenAI   | 标准接口，多语言支持 |
| **DeepSeek Embedding**     | DeepSeek | 性价比高，中文优化   |

**推荐方案**：使用DeepSeek Embedding

### 4.3 API调用成本估算

基于每日采集约30-50篇文章的预估：

| 操作               | 模型               | 预估Token量        | 单价（美元/1K Token） | 每日成本（美元）      |
| :----------------- | :----------------- | :----------------- | :-------------------- | :-------------------- |
| 内容向量化（去重） | DeepSeek Embedding | 30K-50K            | 0.001                 | $0.03-$0.05           |
| 质量打分           | DeepSeek R1        | 10K-15K            | 0.01                  | $0.10-$0.15           |
| 自动分类           | DeepSeek R1        | 5K-8K              | 0.01                  | $0.05-$0.08           |
| 课程大纲生成       | DeepSeek R1        | 10K-20K            | 0.01                  | $0.10-$0.20           |
| 教案生成           | DeepSeek R1        | 15K-30K            | 0.01                  | $0.15-$0.30           |
| **合计**     | -                  | **70K-123K** | -                     | **$0.43-$0.78** |

**月均成本**：约$13-$23（按30天计算）

**成本优化策略**：

- 使用DeepSeek R1（价格约为GPT-4o-mini的1/3）
- 批量向量化减少API调用次数
- 对低质量文章跳过打分和分类环节
- 设置缓存机制避免重复生成

### 4.4 API兼容性设计

采用OpenAI SDK标准接口，通过配置文件切换模型：

```yaml
model:
  provider: deepseek
  api_key: YOUR_API_KEY
  base_url: https://api.deepseek.com
  chat_model: deepseek-r1
  embedding_model: deepseek-embedding
```

## 七、性能优化策略

## 八、日志策略

### 8.1 日志配置

| 配置项       | 说明                                                     |
| :----------- | :------------------------------------------------------- |
| 日志级别     | DEBUG（开发环境）/ INFO（生产环境）                      |
| 日志格式     | `%(asctime)s - %(name)s - %(levelname)s - %(message)s` |
| 日志文件路径 | `logs/app.log`                                         |
| 日志文件大小 | 单个文件最大10MB                                         |
| 日志保留数量 | 保留最近5个日志文件                                      |

### 8.2 日志模块划分

| 模块       | Logger名称    | 日志内容                         |
| :--------- | :------------ | :------------------------------- |
| 采集模块   | `fetcher`   | 信源访问、抓取结果、异常信息     |
| 处理模块   | `processor` | 去重结果、分类结果、打分信息     |
| 生成模块   | `generator` | Prompt构建、API调用、生成结果    |
| 向量库模块 | `vector_db` | 向量存储、相似度搜索、知识库比对 |
| 应用入口   | `app`       | 启动信息、请求处理、全局异常     |

### 8.3 日志级别使用规范

| 级别     | 使用场景                                     |
| :------- | :------------------------------------------- |
| DEBUG    | 详细调试信息（API请求参数、中间结果）        |
| INFO     | 正常业务流程（采集开始/结束、课程生成成功）  |
| WARNING  | 异常但可恢复（信源暂时不可用、数据格式异常） |
| ERROR    | 错误但不影响整体流程（单条数据处理失败）     |
| CRITICAL | 严重错误（系统无法继续运行）                 |

### 8.4 日志初始化代码示例

```python
import logging
from logging.handlers import RotatingFileHandler

def setup_logger(name: str, log_level: str = "INFO") -> logging.Logger:
    logger = logging.getLogger(name)
    logger.setLevel(getattr(logging, log_level.upper()))
  
    # 文件处理器（轮转）
    file_handler = RotatingFileHandler(
        "logs/app.log",
        maxBytes=10*1024*1024,  # 10MB
        backupCount=5,
        encoding="utf-8"
    )
    file_handler.setFormatter(logging.Formatter(
        "%(asctime)s - %(name)s - %(levelname)s - %(message)s"
    ))
  
    # 控制台处理器
    console_handler = logging.StreamHandler()
    console_handler.setFormatter(logging.Formatter(
        "%(levelname)s - %(message)s"
    ))
  
    logger.addHandler(file_handler)
    logger.addHandler(console_handler)
  
    return logger
```

## 九、容错与Mock设计

### 9.1 异常处理层次

| 层次   | 位置         | 处理方式                           |
| :----- | :----------- | :--------------------------------- |
| 采集层 | fetcher.py   | 单条失败记录日志，继续处理其他条目 |
| 处理层 | processor.py | 数据异常跳过，记录错误原因         |
| 生成层 | generator.py | API调用失败重试3次，使用备用模型   |
| 应用层 | app.py       | 捕获全局异常，展示友好提示         |

**Mock数据源**：

- 预置5-10条模拟AI新闻数据
- 包含不同分类、不同质量分数的示例
- 无API Key时自动切换到Mock模式

**Mock运行方式**：

```bash
# 使用Mock数据运行（无需API Key）
python app.py --mock

# 使用真实数据运行
python app.py
```
