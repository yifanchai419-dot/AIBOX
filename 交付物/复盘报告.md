## 一、项目概述

### 1.1 项目背景

AIBOX 是一个自动化 AI 知识聚合与课程生成智能体，旨在帮助教育工作者和团队高效追踪 AI 领域前沿动态。系统每日自动从多个信源采集 AI 资讯，经过智能处理后生成结构化日报，并支持用户基于筛选内容一键生成课程教案。

### 1.2 核心成果

| 指标 | 完成情况 |
|------|----------|
| 核心功能模块 | 5/5（AI 动态、AI 日报、教案生成、文件管理、回收站） |
| 代码实现规模 | 8 个核心源文件，约 1500+ 行 |
| 自动采集信源 | 10 个 RSS + 2 个 API |
| 日报生成 | 每日 6:00 定时自动生成 |
| 教案生成 | 用户主动触发，支持 LLM + Mock 双模式 |
| 云端部署 | 已部署至 Streamlit Cloud |
| 文档交付 | 需求分析文档、技术选型说明、技术文档、README、源代码 |

## 二、开发过程中遇到的主要问题

### 问题 1：UI 按钮文字换行导致显示异常

**问题描述**：
在文件管理页面中，"一键清空"按钮文字因容器宽度不足导致换行，原本单行显示的"一键清空"被折分为两行，影响视觉整洁度。

**根本原因**：
- 按钮设置了 `use_container_width=True`，在窄列布局（列比例 5:1）中被强制拉伸
- 列宽度分配不足，无法容纳按钮文本

**解决方案**：
1. 将列比例从 `[5, 1]` 调整为 `[4, 1]`，给按钮分配更多横向空间
2. 移除按钮的 `use_container_width=True` 属性，改为自适应宽度
3. 调整后按钮恢复单行显示，问题解决

---

### 问题 2：回收站导航索引错误

**问题描述**：
点击侧边栏"回收站"导航项时抛出 `ValueError: '回收站' is not in list` 异常，导致页面无法跳转。

**根本原因**：
- `nav_items` 列表使用 emoji 图标前缀（如 `🗑️ 回收站`）
- `get_icon()` 返回的 emoji 编码与 `nav_items` 中的索引键不匹配
- 直接用 `st.session_state.current_page` 在 `nav_items` 中查找索引失败

**解决方案**：
1. 引入独立的 `page_names` 列表（不含 emoji），与 `nav_items` 一一对应
2. 使用 `page_names.index()` 获取当前页面索引
3. 用该索引渲染 `st.radio` 的导航选项，实现图标显示与导航状态的解耦

```python
# 修复前
current_idx = nav_items.index(st.session_state.current_page)

# 修复后
page_names = ["AI动态", "AI日报", "教案生成", "文件管理", "回收站"]
current_idx = page_names.index(st.session_state.current_page)
selected_nav = st.radio("", nav_items, index=current_idx, ...)
```

### 问题 3：文件恢复失败（目标目录不存在）

**问题描述**：
用户从回收站恢复文件时，文件未能正确还原到原始目录。例如恢复日报文件时，因 `output/daily_reports/` 目录不存在导致 `os.rename()` 失败。

**根本原因**：
- 文件管理页面的目录结构（如 `daily_reports/`）是在用户首次访问时才创建
- 回收站恢复操作时未检查目标目录是否存在
- 用户可能从未访问过文件管理页面，导致目标目录尚未创建

**解决方案**：
在 `restore_from_recycle_bin()` 函数中，执行 `os.rename()` 前添加目录自动创建逻辑：

```python
os.makedirs(os.path.dirname(restore_path), exist_ok=True)
os.rename(recycle_path, restore_path)
```

确保无论用户是否访问过文件管理页面，恢复操作都能正确执行。

### 问题 4：时区显示错误

**问题描述**：
文件管理页面中，日报和教案的生成时间显示错误。例如实际 13 点生成的文件被显示为 5 点（UTC 时间），而教案文件显示时间却正常。

**根本原因**：
- `scheduler.py` 使用 `datetime.now()` 生成调度器日志时间
- 但保存文件时使用的时间戳未明确转换为北京时间
- `os.path.getmtime()` 返回的是 UTC 时间，直接显示未做时区转换
- 教案生成时可能通过其他方式记录时间，所以显示正常

**解决方案**：
在所有文件时间显示处，统一使用显式的时区转换：

```python
from datetime import timezone, timedelta

# UTC 时间转换为北京时间
beijing_tz = timezone(timedelta(hours=8))
display_time = datetime.fromtimestamp(file_mtime, tz=beijing_tz)
```

修复后所有文件时间均准确显示为北京时间。

### 问题 5：回收站项目布局不整齐

**问题描述**：
回收站中的文件类型标签（"日报"/"教案"）与文件名之间存在间距过大或换行问题，导致显示不整齐。

**根本原因**：
- 文件名使用 `overflow: hidden` 但类型标签未设置 `flex-shrink: 0`
- 在内容溢出时，类型标签可能被挤压或换行

**解决方案**：
使用 CSS flexbox 布局，为类型标签添加 `flex-shrink: 0` 防止被压缩，文件名添加 `overflow: hidden` 和 `text-overflow: ellipsis` 实现省略号显示，确保标题与标签始终在同一行。

### 问题 6：AI 日报页面与 MD 文件内容不一致

**问题描述**：
AI 日报页面显示"模型发布"分类有 28 篇文章，但对应 MD 文件中仅能找到 10 篇文章，两个渠道获取的内容数量严重不一致。

**根本原因**：
- 日报页面使用实时抓取的最新文章数据
- MD 文件使用定时任务生成时的缓存数据
- 两处数据来源不同，且无强制同步机制
- 生成 MD 时可能过滤部分文章，但页面未同步过滤

**解决方案**：
1. 修改 MD 文件生成逻辑，确保使用与 AI 日报页面完全一致的文章数据
2. 在生成 MD 文件时，使用全部文章而非仅 Top N
3. 确保 MD 文件中的文章分类与排序规则与页面展示完全相同
4. 统一按评分从高到低排序，保证两个渠道输出一致

---

### 问题 7：教案功能定位误解

**问题描述**：
项目文档中曾将教案描述为"自动生成"，但实际教案需要用户主动选择文章后才触发生成。

**根本原因**：
- 初始需求文档中对教案生成方式的描述不够清晰
- 教案生成需要用户根据自身教学需求挑选文章，具备个性化特征
- 若自动生成则失去了人工筛选的价值

**解决方案**：
1. 明确区分日报（自动生成）与教案（手动生成）的定位
2. 更新所有文档和 UI 描述，统一说明教案需用户主动操作
3. 在 README 和技术文档中增加"教案生成需用户主动选择文章后触发"的注意事项
4. 在 UI 界面中增加引导提示，说明"勾选感兴趣的文章后点击生成按钮"

## 三、问题解决经验总结

### 3.1 问题分类与应对策略

| 问题类型 | 出现次数 | 典型特征 | 应对策略 |
|----------|----------|----------|----------|
| UI 布局问题 | 3 次 | 显示异常、换行、对齐不齐 | 使用 CSS flexbox、调整列比例 |
| 状态同步问题 | 2 次 | 数据不一致、页面跳转失败 | 引入独立索引、统一数据源 |
| 时区/时间问题 | 1 次 | 显示值与实际不符 | 显式时区转换函数封装 |
| 文件系统问题 | 1 次 | 恢复失败、路径不存在 | 操作前自动创建目录 |
| 需求理解问题 | 1 次 | 功能定位描述偏差 | 核实实际行为，更新文档说明 |

### 3.2 有效实践

1. **分层解耦**：将导航显示（含图标）与页面路由（纯文本）分离，避免耦合导致的错误
2. **防御性编程**：在文件操作、目录操作前主动检查和创建依赖项
3. **一致性优先**：UI 展示与文件存储使用统一的数据源和处理逻辑
4. **用户引导**：在 UI 中增加清晰的操作提示，减少用户误解
5. **跨平台测试**：关注时区、编码等平台差异导致的问题

## 五、项目总结

### 5.1 核心价值

AIBOX 项目成功实现了从 AI 资讯采集、智能处理、日报生成到教案制作的全流程自动化。系统具备以下核心价值：

- **效率提升**：将人工每日整理 AI 资讯的时间从 2~3 小时缩短至 0（全自动）
- **质量保证**：通过四维打分模型和五级分类体系，确保输出内容的质量和规范性
- **灵活扩展**：支持 10+ 信源配置，可快速扩展信源覆盖范围
- **稳定可靠**：三级降级机制（ChromaDB→TF-IDF→Jaccard、LLM→Mock）确保系统在任何环境下均可正常运行

### 5.2 经验启示

1. **文档先行**：在开发过程中，清晰的需求文档和技术文档能够有效避免功能定位误解
2. **小步快跑**：采用敏捷迭代方式，每个功能模块独立开发和测试，降低集成风险
3. **用户反馈驱动**：及时响应用户的 UI 反馈和体验问题，快速迭代改进
4. **防御性编程**：文件操作、网络请求等关键点需有完善的异常处理和回退机制
